Feature + Fix

Feedback loop: thumbs up/down on answers

2026-09-17 15:49
What

POST /queries/:id/feedback (accepts exactly 'up', 'down', or null) stores per-answer feedback in a new feedback column, mirroring the earlier pin feature's migration and ownership pattern. ChatPage.jsx adds thumbs-up/down buttons with an optimistic toggle.

Why

Continuing the feature list "biggest to smallest" — #20 on the list. A caveman subagent review caught two real issues, both fixed: the optimistic-update revert-on-failure could clobber a newer, already-successful request from a rapid double-click (fixed with a compare-before-revert guard), and the "ownership" test only checked a nonexistent id, never a real cross-user bypass (fixed by adding a second session and asserting 404). An ecc security review confirmed the route is auth-gated, ownership-scoped, and strictly input-validated.

Feature

Share options for any answer

2026-09-17 15:35
What

A Share button next to each assistant message's copy/read-aloud/pin buttons calls navigator.share({ text }) (native OS share sheet on mobile/supporting browsers) and falls back to navigator.clipboard.writeText(text) with a brief "Copied for sharing!" confirmation when the Web Share API isn't available.

Why

Continuing the feature list "biggest to smallest" — #2 on the list. A caveman subagent review caught one real issue before commit: the navigator.share rejection handler treated a user cancelling the OS share sheet the same as a real failure, silently falling through to a clipboard copy the user never asked for. Fixed by checking for AbortError and returning early on a genuine cancel. An ecc security review confirmed no untrusted data is involved — only the AI's own already-rendered response text is passed.

Feature + Fix

Smart follow-up suggestions, and a live safety-classifier bug fix

2026-09-17 15:19
What

server/suggestions.js generates 2-3 short follow-up questions after each chat answer, rendered as clickable chips under the latest assistant message; reuses whichever adapter just answered, capped at an 8s non-throwing timeout. Separately, server/response-sanity.js detects when OpenRouter's free auto-router lands on a safety/moderation model and returns fixed-format text like "User Safety: safe" instead of a real answer — previously only caught inline in memory extraction, now centralized and wired into server/router.js's core adapter loop.

Why

Continuing the feature list "biggest to smallest." While live-testing suggestions, a real question ("What is the tallest mountain in the world?") came back with the safety-classifier garbage as its actual visible answer — the same OpenRouter flakiness previously seen only in a background memory-extraction call, now confirmed hitting real user-facing responses. Fixed at the correct layer (the router's fallthrough loop, not just memory.js). A caveman subagent review caught two real issues before commit, both fixed: the suggestions call had no outer timeout of its own, and the suggestion chips used the suggestion text as a React key — fragile against duplicates, switched to an index key.

Feature + Fix

Cross-conversation memory, crisp answers, cloud-first routing

2026-09-17 11:23
What
  • Built server/memory.js to extract and remember durable facts about the user across separate conversations, injected into future system prompts via a new optional extraContext parameter on both adapter factories.
  • Rewrote the general/coding system prompts — the old wording ("well-organized", "well-explained") was producing essay-length, over-structured answers to simple questions.
  • Reordered DEFAULT_ADAPTERS/CATEGORY_PRIMARY in server/router.js to try OpenRouter before Ollama.
Why

Memory was requested after the crispness issue surfaced live — "what all ai's are working in the backend" returned an 8-section generic essay about AI infrastructure in general, nothing about OmniAgent's own backend. The reorder fixed a diagnosed problem: local Ollama (0% GPU, confirmed) was taking 10-20s+ per attempt, twice per message — up to ~40s of timeouts before reaching a cloud answer that would've come back in seconds anyway. This also delivers "online use the online tools, offline use the offline tools" for free, with no explicit connectivity detection. Also fixed live: memory-extraction initially used OpenRouter's free auto-router, which landed on a safety/moderation model and returned "User Safety: safe" as a stored "fact" — fixed by reusing whichever adapter had just successfully answered.
